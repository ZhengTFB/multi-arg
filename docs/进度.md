## 2026-10-31 · 设计修订（用户三条反馈）

### 1. 文案可以在浏览器里改，改完写回文件

- 所有界面文字集中到 `src/copy.json`（81 条），组件通过 `src/lib/copy.ts` 的 `t(key)` 取值，需要点选改的元素带 `data-copy="key"`。
- `?edit=1` 打开校对模式：点任何带 `data-copy` 的文字就地改（contentEditable），底部工具条显示改了几处。
- 「列表」按钮打开全部文案（含占位符这类不在正文里的），可以直接改。
- 保存走 dev 中间件 `POST /__copy/save`（`vite.config.ts` 里 `configureServer`），合并写回 `src/copy.json`，写完自动刷新。构建产物里没有任何写文件能力。
- 验证过程（Playwright）：改标题 → 保存 → 文件中出现新值 → 刷新后页面渲染新值 → 再改回原值，四步都通。

```
toolbar: 1
written: 几个人一起翻同一件案子
rendered: 几个人一起翻同一件案子
list rows: 81
restore: 200 几个人一起玩网页解谜
```

## 2026-11-01 · 第六轮：真后端（Phase 2 的数据层）

**做了什么**

- 新增 `server/`：Node 24 内置 `node:sqlite` 存房间/成员/条目，`ws` 做房间长连接，`server/index.mjs` 一个进程同时托管 `dist/`、`/api`、`/ws`（单端口，没有跨域和代理问题）。
- 接口：`POST /api/room`（建房）、`POST /api/room/:id/join`、`GET /api/room/:id`（房名/人数）、`GET /api/room/:id/state?member=`（刷新换回身份）、`GET /api/health`。
- 长连接协议：`snapshot` / `item.add` / `item.patch` / `member.update` / `presence` / `error`，30 秒心跳；前端 `RoomSocket` 指数退避重连（1s→15s），重连后重新拿快照。
- 写入一律由服务端落库后广播，服务端补 `id` / 作者 / 时间；**只有作者能改自己的条目**（越权返回 `not_owner`，前端静默忽略）。
- 房间规则：4 位房间号、无口令、IP 限流 30 次/分钟；成员身份存 `arg:member:<房间号>`；7 天后只读、第 37 天清库。
- 前端：删掉 `src/lib/mock.ts`，`Room` 改成「先换身份 → 再连长连接」，`Setup` 真实建房后跳转；星标/排除/关键词/密码验证全部走 `item.patch`。
