# 03-网页代理

# 多人 ARG · 网页代理

**这份管**：`/p` 路由的全部实现。签名、抓取、HTML 改写、bridge 注入、302、降级、安全。
**这份不管**：代理地址在界面上怎么拼（01 §2.8）、房间元信息怎么存（02 §1）。

**这一节是整个项目最需要精确实现的部分。** 别自己发挥。

---

## 1. 入口与签名

```
GET /p?u=<encoded absolute url>&r=<roomId>&s=<hmac>
```

`s = HMAC-SHA256(PROXY_SECRET, u + '|' + r)` 的前 16 字节 hex。

- `PROXY_SECRET` 是 Worker secret，`wrangler secret put PROXY_SECRET`。
- iframe 初始 src 由 `POST /api/room` 返回；页面里的链接由代理重写时现场签。
- 客户端拿不到 secret，外部无法把 `/p` 当开放代理用。
- 校验失败 → `403`，body 一句 `链接已失效，刷新一下。`

**为什么必须签名**：`/p?u=` 一旦公开可用，就是一个免费代理，会被人拿去刷流量、当跳板。签名的成本是三行代码。

**刷新怎么办**：iframe 的 src 存 `sessionStorage`。没有就调 `GET /api/frame?r=<id>&token=<token>` 重新签一个，不要重建房间。

---

## 2. 请求流程

```
1. 解析 u，协议必须是 https（http 也收，强转 https 再试一次）
2. 拒绝私有地址：localhost、127.*、10.*、192.168.*、172.16-31.*、*.local、[::1]
3. fetch，请求头带：
   User-Agent: <写死一个 iPad Safari 的完整 UA>
   Accept: text/html,application/xhtml+xml,...
   Accept-Language: zh-CN,zh;q=0.9
   Referer: <目标站 origin>/
   ⚠️ 不要带 accept-encoding。带了会拿到压缩流，HTMLRewriter 会报错。
4. 按 content-type 分流：text/html → §3，其余 → §5
```

**base 用 **`response.url`**，不是请求的 **`u`**。** fetch 跟过重定向后最终地址可能不一样，`response.url` 才是这一页真正的地址。用错了，所有相对链接会指到错的地方。

---

## 3. HTML 改写

用 `HTMLRewriter`，顺序不能变。

### a. 注入 base

`<head>` 最前面插 `<base href="<最终 URL>">`。相对路径在浏览器侧自然解析到原站。

**原页面已经有 **`<base>`** 的话，分两种：**

- 原 base 和页面同源 → 删掉，换成我们的
- 原 base 指向别的域名（CDN）→ **保留它，不要插第二个**。浏览器只认第一个 `<base>`，插了也没用；而它多半是靠那个 CDN 解析图片和脚本的，删了会白屏。这种站通常资源全是绝对地址，不依赖我们的 base。

四个推荐项目里，`contemporary.minis.yoroll.ai` 属于第二种，`<base>` 指向 `d1rbt3w1v12ruj.cloudfront.net`。别动它。

顺带说，这站自己有一段脚本会检查 base：base 跨域就把它 `removeChild` 掉。所以就算我们不动，它也自己会删，然后按当前 URL 解析——这正是它能在别人的 iframe 里活着的原因。

### b. 重写导航链接

`a[href]` 和 `form[action]`：解析成绝对 URL。同源的改写成签名后的 `/p` 地址；跨域的保持原样。

```js
.on('a[href]', {
  element(el) {
    const h = el.getAttribute('href')
    if (!h || h.startsWith('#') || h.startsWith('javascript:')) return
    let abs
    try { abs = new URL(h, baseUrl) } catch { return }
    if (abs.origin === baseOrigin) {
      el.setAttribute('href', signedProxyUrl(abs.href, roomId))
    }
  }
})
```

`form[action]` 同理，method 不变。没有 `action` 的表单默认指向当前页，也要补上。

### c. 资源直连

`img[src]`、`script[src]`、`link[href]`、`source[src]`、`video[poster]`：改成绝对 URL，让浏览器绕过我们。

这一步是流量的全部秘密。图片一个字节都不过 Worker。

同时给 `img` 和 `video` 加 `referrerpolicy="no-referrer"`。有些站检查 Referer，直连时浏览器带的还是代理页地址，会被判盗链直接 403。

### d. 去掉会打架的属性

- 删 `integrity`（改了资源地址后哈希对不上，SRI 会直接拦掉）。
- 删 `crossorigin`。
- `a[target="_blank"]` 保留，但加 `rel="noopener"`。

### e. 隔离 localStorage

**这一步不做，代理一开，所有玩家的进度会串在一起。**

实测这几个作品都把进度存在 `localStorage` 里：论坛站存 `gamePassword`、`chatGameState`、`forumUserPosts`，yoroll 那部存 `storyPhase1Completed`、`pukuHoaxResolved`。直连时各自浏览器分开，没问题；一旦走代理，所有 HTML 都来自我们这一个域名，`localStorage` 按 origin 隔离，于是整个房间共用一个存档——A 玩到第三章，B 一进来直接第三章。

在 bridge 里加前缀隔离：

```js
(function () {
  var PREFIX = '__arg:' + ROOM_ID + ':' + USER_ID + ':';
  var raw = window.localStorage;
  function p(k) { return PREFIX + k; }

  var shim = {
    getItem: function (k) { return raw.getItem(p(k)); },
    setItem: function (k, v) { raw.setItem(p(k), String(v)); },
    removeItem: function (k) { raw.removeItem(p(k)); },
    clear: function () {
      var del = [], i, k;
      for (i = 0; i < raw.length; i++) {
        k = raw.key(i);
        if (k && k.indexOf(PREFIX) === 0) del.push(k);
      }
      for (i = 0; i < del.length; i++) raw.removeItem(del[i]);
    },
    key: function (n) {
      var c = 0, i, k;
      for (i = 0; i < raw.length; i++) {
        k = raw.key(i);
        if (k && k.indexOf(PREFIX) === 0) {
          if (c === n) return k.slice(PREFIX.length);
          c++;
        }
      }
      return null;
    }
  };
  Object.defineProperty(shim, 'length', {
    get: function () {
      var c = 0, i, k;
      for (i = 0; i < raw.length; i++) {
        k = raw.key(i);
        if (k && k.indexOf(PREFIX) === 0) c++;
      }
      return c;
    }
  });

  try {
    Object.defineProperty(window, 'localStorage', { value: shim, configurable: true });
  } catch (err) {
    var proto = Storage.prototype;
    var o = { g: proto.getItem, s: proto.setItem, r: proto.removeItem };
    proto.getItem = function (k) { return this === raw ? o.g.call(this, p(k)) : o.g.call(this, k); };
    proto.setItem = function (k, v) { return this === raw ? o.s.call(this, p(k), v) : o.s.call(this, k, v); };
    proto.removeItem = function (k) { return this === raw ? o.r.call(this, p(k)) : o.r.call(this, k); };
  }
})();
```

`sessionStorage` 照抄一遍，把 `window.sessionStorage` 和 `Storage` 换成对应的。多数作品两个都用。

`ROOM_ID` 和 `USER_ID` 由 `/p` 路由拼进这段脚本（服务端注入，不用 URL 参数，省得玩家改）。`USER_ID` 是房间内的成员 id，不是账号。

**已知的边界：**

- 前缀隔离只在同一个浏览器里有效。换设备、换浏览器，进度是另一份。这是浏览器的限制，接受。
- 玩家从代理切到直连，进度会断（两边 key 不同）。所以 7 节降级时**必须提示**：`切到直连后，游戏里的存档要重新来。` 不要静默切换。
- 直接用 `localStorage.foo = 1` 这种属性写法赋值，前缀拦不住。这几种作品都用的标准 API，实测没有这种写法。发现哪个作品用了，单独给它记进 `DECISIONS.md`。

### f. 注入 bridge

在 `</body>` 前插：

```html
<script>
(function () {
  var t;
  function send() {
    try {
      parent.postMessage({
        __arg: 1,
        url: document.baseURI || location.href,
        title: document.title,
        scrollY: window.scrollY
      }, '*');
    } catch (e) {}
  }
  function debounce() { clearTimeout(t); t = setTimeout(send, 120); }
  addEventListener('load', send);
  addEventListener('popstate', send);
  addEventListener('hashchange', send);
  var ps = history.pushState, rs = history.replaceState;
  history.pushState = function () { ps.apply(this, arguments); debounce(); };
  history.replaceState = function () { rs.apply(this, arguments); debounce(); };
})();
</script>
```

注意 `document.baseURI`，不是 `location.href`。后者是代理地址，没用。

### g. 返回

`Content-Type: text/html; charset=utf-8`，不加 CSP，不加 `X-Frame-Options`，`Cache-Control: private, max-age=60`。

## 4. 父页面校验

`event.origin === location.origin` 且 `event.data.__arg === 1`。

收到后：

1. `proxyOk = true`
2. 更新 `latestPageUrl`、`latestTitle`
3. 发 `page` 消息上报（节流 5 秒）
4. url 变了就更新"正在看"的状态

---

## 5. 非 HTML

一律 `302` 到原 URL：

```
Location: <原始绝对 URL>
Cache-Control: public, max-age=3600
```

图片、CSS、JS、字体全部由浏览器直连原站，Worker 只吐一个 302，几百字节。

`text/css` 也 302。不要试图改写 CSS 里的 `url()`，收益小，风险大。

---

## 6. POST

`POST /p?u=...` 时，body 和 `content-type` 原样转发，返回按 §3 / §5 处理。

站内搜索多数是 GET，但有的用 POST，不处理会静默失败。

**注意**：POST 之后的重定向可能丢 body。目标返回 3xx 时，直接把 `Location` 透给浏览器，不要二次请求。

## 7. 失败检测与降级

`iframe.onload` 后启动 2500ms 计时器。没收到任何 `__arg` 消息：

- 顶部浮一条：`这一页可能没加载完整。` 后面一个 `换直连`
- 点它 → `game.proxy = false`，iframe 换成原站 URL，重载
- **不要自动切。** 用户点才切

切了直连之后：

- "钉住这页"走剪贴板路径（§9）
- 面板头部显示一个小字 `直连`，点它可以切回代理

**切之前必须说一句**：`游戏里的存档会重新开始。`

因为代理和直连是两个 origin，`localStorage` 不互通。玩家在代理里玩到第三章，一切直连就回到开头。这不是 bug，是浏览器的隔离规则，只能靠提前说清楚。

提示放在 `换直连` 按钮的确认弹层里，两个按钮：`换（存档重来）`、`先不换`。

切回代理也一样，存档同样从代理那份继续，不是直连那份。两个存档各自独立存在，谁都没被删。

## 8. 不能嵌入的站

`probe` 时发现 `X-Frame-Options: DENY/SAMEORIGIN` 或 `CSP frame-ancestors`：

- 房间照样能建，但 `embeddable = false`
- 进房后 iframe 位置显示一张卡：`这个网页不支持嵌入。` 两个按钮：`在新窗口打开`、`仍然试试`
- "在新窗口打开" → `window.open(game.url)`，流照常用（只是拿不到"正在看哪页"）
- 不要因为嵌不进去就挡住用户。发链接、聊天、笔记都不受影响

**光看响应头会漏。** 微信的 `mp.weixin.qq.com` 不返回 `X-Frame-Options`，但页面脚本会检查环境，在 iframe 里直接跳走或者显示"请在微信中打开"。这类站只能靠实测：本地 `index.html` 里塞一个 iframe 指过去，打开看它是不是白的。

`games.json` 里已经标了 `embeddable: false` 的，不要再试一遍。

---

## 9. 直连模式下发链接

点"钉住这页"时：

1. `latestPageUrl` 存在且 3 分钟内更新过 → 直接用
2. 否则读剪贴板 `navigator.clipboard.readText()`，读到 http(s) URL 就填入
3. 都拿不到 → 显示输入框，占位符 `粘贴这一页的地址`

第 2 步能自动读，是因为点按钮本身是用户手势。

---

## 10. 安全

- 只允许 http/https。
- 禁内网地址（§2 第 2 步）。
- **不转发 Cookie，不转发 Set-Cookie。** 代理无状态。
- 不转发 `Authorization`。
- 响应头里删掉 `Content-Security-Policy`（否则原站的 CSP 会把注入的 bridge 拦掉）、`X-Frame-Options`、`Set-Cookie`。
- 单次响应体上限 3MB，超了返回 `这个页面太大了。`
- 超时 15 秒，超了返回 `这个页面加载超时。`

---

## 11. 已知会坏的情况

提前知道，别到时候以为是 bug。

| 情况 | 表现 | 处理 |
| --- | --- | --- |
| 站点用 `fetch()` 拉数据 | 页面白屏或数据空，但 bridge 有消息 | 无解，引导用户切直连 |
| 站点检查 `Referer` 防盗链 | 图片 403 | 已加 `referrerpolicy`，仍失败就换直连 |
| 站点有 Service Worker | 注册失败，通常不影响 | 忽略 |
| 站点用绝对路径写死自己的域名 | 跳回原站，URL 丢 | 无解，用户手动粘 |
| 站点是 SPA，路由在 hash 里 | 正常，bridge 能拿到 | 无 |
| 站点很大（\>3MB HTML） | 超时或超大提示 | 切直连 |
